- **[2026-04-10] Dead CTA buttons shipped to prod**: The landing page's `.btn-primary / .btn-secondary / .btn-cta` handlers contained a `console.log('Button clicked', ...)` stub with the comment `"For now, just log (in production, these would navigate)"`. It shipped. Login link also had `href="#"`. Blog/terms/privacy pages pointed to `/login` which is not a route (server only serves `/app.html`). **Rule**: any time I ship a marketing/landing page, I must verify every interactive element has a real destination. Grep for `href="#"`, `console.log`, `// TODO`, and "for now" in any template before marking it done. Also: never use bare `<button>` for nav/CTA links — use `<a>` so broken JS still routes.

- **[2026-04-10] Rebrand rewrite replaced real API data with hardcoded mock newsletters**: Same `92b50d6 feat(brand): ship brv. logo` full-file rewrite not only broke the React CDN (see below) but also silently switched `App` from fetching `/api/newsletters` + `/api/tags` to hardcoded `mockNewsletters` (6 fake items: "Morning Brew", "The Information", etc.) and `mockTags` (5 colors). When the CDN was later fixed, users saw a working app — but one rendering placeholder demo data instead of their real 128 newsletters. User reported "all my newsletters have been lost"; they were never lost, the DB was fine, the UI just stopped asking. **Rules**: (1) a full-file rewrite of a working production file is an incident waiting to happen — always diff against origin/main before commit and scan for `mock*`, `sample*`, `fake*`, `placeholder`, `TODO` identifiers. (2) After touching a data-bound component, verify the live page shows data that matches what `/api/*` returns — don't assume "the page renders" means "the page works." (3) Normalize API field names at one chokepoint (a `normalize*` function), not inline at render sites, so snake_case ↔ camelCase mismatches can't hide in multiple places.

- **[2026-04-10] Full-file rewrite corrupted React CDN path → blank /app.html for everyone**: The `92b50d6 feat(brand): ship brv. logo` commit was a sweeping rewrite of `public/app.html` that accidentally changed `cdnjs.cloudflare.com/ajax/libs/react/18.2.0/umd/react.production.min.js` → `.../18.2.0/react.production.min.js` (dropped the `/umd/` segment). cdnjs returned 503 for the bad path, `React` and `ReactDOM` became `undefined`, and line 1 of the babel block (`const { useState, useEffect, useRef } = React`) threw a `ReferenceError` before anything rendered. Blank white screen. I then spent hours "fixing" auth wiring and adding an ErrorBoundary to diagnose — none of which could ever have helped because React itself wasn't loading. **Rules**: (1) NEVER do a full-file rewrite of a working production file — use targeted Edits so the git diff is reviewable. (2) After ANY change that touches `<script src>` or `<link href>` tags, open the deployed URL in Chrome MCP and verify `read_network_requests` shows every asset returning 200. (3) If a page goes blank, the FIRST debugging step is always `read_network_requests` + `read_console_messages` — check whether the runtime even loaded before touching application code. (4) Use unpkg.com (React's canonical CDN) with a jsdelivr fallback via `document.write`, so a single CDN outage never bricks the app. (5) Recognize the smell: "I'm adding instrumentation to understand a blank page" is a cue to re-check the basics, not to keep piling on code.
